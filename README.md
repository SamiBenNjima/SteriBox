# SteriBox — UV Sterilization System (Arduino/ESP32)

Medical-grade UV sterilizer controller built on two ESP32-S3 boards communicating over UART.

---

## System Overview

```
┌──────────────────────────────────┐       UART (115200 baud)       ┌──────────────────────────────┐
│   ESP32-S3 DevKit (Master)       │ ◄─────────────────────────────► │  ESP32-S3 CrowPanel 5"       │
│   SteriBox_S3_Master.ino         │  TX(17)→RX(44) / TX(43)→RX(18) │  UI-2/UI/UI.ino              │
│                                  │                                  │  + steribox_app.c (LVGL UI)  │
│  • 2× UV lamp relays (GPIO 1/2)  │                                  │   Home / Config / Info screens│
│  • Piezo buzzer  (GPIO 3, PWM)   │                                  │                              │
│  • Door / PIR sensor (GPIO 4)    │                                  │  • SD card logging           │
│  • DHT22 temp+hum (GPIO 5)       │                                  │  • NVS persistence           │
│  • Cooling fan   (GPIO 6)        │                                  │  • DS3231 RTC (slave-local)  │
│  • DS3231 RTC I2C (SDA=8 SCL=9) │                                  │                              │
│  • USB-OTG port  (GPIO 19/20)    │                                  │                              │
│    → USB printer / flash drive   │                                  │                              │
└──────────────────────────────────┘                                  └──────────────────────────────┘
```

### USB Ports — Master (ESP32-S3 DevKit)

| Port | Use |
|---|---|
| **USB-UART** (CH340 chip) | Arduino IDE upload · Serial Monitor · debug |
| **USB-OTG** (native S3) | USB devices — printer (CDC) · USB drive (MSC) |

> GPIO 19 / 20 are reserved for USB-OTG D−/D+. Do **not** wire anything else to them.

### Folders

| Path | Description |
|---|---|
| `UI-2/SteriBox_S3_Master/` | **New** ESP32-S3 DevKit master firmware |
| `UI-2/SteriBox_Master/` | *(Legacy — old ESP32-S master, kept for reference)* |
| `UI-2/UI/` | ESP32-S3 CrowPanel UI firmware (LVGL — Home / Config / Info screens) |

Inside `UI-2/UI/`, the SteriBox logic (everything not generated by SquareLine):

| File | Role |
|---|---|
| `steribox_app.c` | cycle state machine, UV-C dose model, cycle records, screens wiring |
| `steribox_hal.h` / `steribox_hal_esp32.cpp` | hardware abstraction: relays, RTC, SD, streaming file writer |
| `steribox_uart.c/h` | UART link to the master, including the file tunnel |
| `sbx_report.c/h` | one cycle record → printer ticket, CSV ledger row, PDF |
| `sbx_pdf.c/h` | dependency-free streaming PDF 1.4 writer |

| Sensor | Door switch or PIR sensor |
| USB devices | Printer (CDC) or USB drive (MSC) via OTG port |

### Wiring (UART link)

| Master (ESP32-S3 DevKit) | Slave (CrowPanel S3) |
|---|---|
| TX → GPIO 17 | RX → GPIO 44 |
| RX → GPIO 18 | TX → GPIO 43 |
| GND | GND |

### Master GPIO Map

| Function | GPIO | Notes |
|---|---|---|
| Relay 1 (UV lamp 1) | 1 | Active LOW |
| Relay 2 (UV lamp 2) | 2 | Active LOW |
| Buzzer | 3 | LEDC PWM 2700 Hz |
| Door / PIR sensor | 4 | HIGH = open / motion |
| DHT22 data | 5 | 10 kΩ pullup to 3.3 V |

| USB-OTG D− | 19 | **Reserved** — OTG port |

## Installation

### 1 — Clone the repository

```bash
git clone https://github.com/<your-username>/SteriBox.git
cd SteriBox/arduino
git checkout feature/esp32s3-master
```

### 2 — Install the ESP32 board package

1. Open Arduino IDE → **File → Preferences**
2. Paste the URL above into *Additional boards manager URLs*
3. Open **Tools → Board → Boards Manager**, search `esp32`, install **esp32 by Espressif ≥ 3.0**

### 3 — Flash the Master (ESP32-S3 DevKit)

1. Open `UI-2/SteriBox_S3_Master/SteriBox_S3_Master.ino`
2. Select **Board**: `ESP32S3 Dev Module`
3. Select **USB Mode**: `Hardware CDC and JTAG` (uses the CH340 debug port)
4. Select the correct COM port (the one that appears when you plug the **USB-UART** port)
5. Click **Upload**

### 4 — Flash the Slave UI (CrowPanel ESP32-S3)

1. Open `UI-2/UI/UI.ino`
2. Select **Board**: `ESP32S3 Dev Module` (or your CrowPanel variant)
3. Select the correct COM port
4. Click **Upload**

### 5 — Power up

Connect both boards, wire UART + GND (see wiring table above), then power on.
The CrowPanel will show the Home screen; the master begins sending telemetry
(temp / humidity / relay states) every 500 ms.

## UART Protocol

Defined in `sbx_uart_protocol.h` (kept byte-identical in both sketch folders).

| Field | Size | Notes |
|---|---|---|
| `header` | 1 byte | `0xAA` Master → Slave, `0xBB` Slave → Master |
| `type` | 1 byte | Message/command identifier |
| `data` | 4 bytes | Payload |
| `checksum` | 1 byte | XOR of all preceding bytes |

Key message types: `TELEMETRY`, `CMD_SET_RELAY`, `CMD_SET_BUZZER`, `CMD_PING` / `MSG_PONG`,
`CMD_PRINT`, and the file-transfer trio `CMD_FILE_OPEN` / `CMD_FILE_DATA` /
`CMD_FILE_CLOSE` answered by `MSG_FILE_ACK`.

File transfers carry a 1-byte length in `data[0]` and up to 3 payload bytes in
`data[1..3]`, which keeps them binary-safe (a PDF contains `0x00`) at roughly
4.3 kB/s — a one-page report lands in about two seconds.

## Cycle records, logging and reports

**Every cycle is recorded** — completed or not. A cycle stopped by the operator,
or auto-cancelled after the door was left open past the 10 s pause window, gets
the same sequence number, the same ledger row and the same printable ticket as a
successful one; only its result and reason differ.

Each cycle end writes three artefacts to `/steribox/` on the SD card:

| File | Contents |
|---|---|
| `syslog.csv` | one timestamped event row (`CYCLE_DONE` / `CYCLE_CANCELLED`, `DOOR_PAUSE`, `BOOT`, `EXPORT`, config edits) |
| `cycles.csv` | the ledger — one fully machine-readable row per cycle, self-describing header written on creation |
| `ticket_NNNNN.txt` | the exact printer ticket for that cycle, so it can be recovered or reprinted later |

Tickets and reports state **lamp active time** — wall-clock seconds with a
ballast energised, preheat included and door pauses excluded, broken down per
tube. This is deliberately *not* the same figure as the equivalent exposure
used by the dose model: during the 180 s amalgam ramp the lamps are on but
delivering 25→100 % of their output, so the equivalent seconds are always
lower. Operators read lamp-on time; the dose model reads equivalent seconds.

The ticket, the PDF and the CSV row are all rendered from one `sbx_report_t`
(`sbx_report.c`), so they cannot disagree about what a cycle delivered.

### PDF export

**Info → Export** asks for a date range and writes a styled A4 PDF: dark title
band, zebra-striped tables, a per-organism log-reduction bar chart coloured by
verdict against the 4-log acceptance line, and the machine-state block.

The PDF is produced by `sbx_pdf.c`, a dependency-free PDF 1.4 writer. Nothing is
buffered — not even the current page: each content stream declares its size
through an indirect `/Length` object written after the stream, so a report of any
length is emitted in a single forward pass and streamed straight to the
destination. It uses the two standard Helvetica faces, so no font data ships on
the device.

The export target is a **USB flash drive** on the master's OTG port. When no
drive is mounted the PDF is written to the SD card instead and the operator is
told so.

## USB-OTG (printer / flash drive)

The ESP32-S3 DevKit's native USB-OTG port (the second USB-C connector) is
reserved for USB devices, behind two independent build switches in
`SteriBox_S3_Master.ino`:

| Switch | Default | What it enables |
|---|---|---|
| `SBX_USB_OTG_ENABLED` | `0` | CDC printer host (ticket printing) |
| `SBX_USB_MSC_ENABLED` | `0` | Mass-storage host — mounts a FAT drive at `/usb` for PDF export |

`SBX_USB_MSC_ENABLED` needs the ESP-IDF USB MSC host component, which is **not**
part of the Arduino core. Build with PlatformIO/ESP-IDF and add to
`idf_component.yml`:

```yaml
dependencies:
  espressif/usb_host_msc: "^1.1.0"
```

While the switch is `0` the master never raises `SBX_FLAG_USB_DRIVE`, the slave
sees "no USB drive", and PDF exports fall back to the SD card. Everything else
in the export path — PDF generation, the UART file tunnel, the abort-on-failure
handling — is live either way.

> Both devices share the single OTG port. A printer and a flash drive cannot be
> attached at the same time without a USB hub.
