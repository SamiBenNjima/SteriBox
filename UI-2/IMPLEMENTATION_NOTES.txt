/**
 * STERIBOX MASTER/SLAVE ARCHITECTURE - Implementation Summary
 * ============================================================
 *
 * PROBLEM SOLVED:
 *   ESP32-S3 CrowPanel 5" uses almost every GPIO for the RGB display bus + touch I2C.
 *   Solution: separate ESP32-S "GPIO Master" board handles all peripheral I/O,
 *   communicates with the CrowPanel over UART (non-blocking, cached telemetry).
 *
 * ============================================================
 * MASTER (ESP32-S DevKit) - GPIO Controller
 * ============================================================
 *
 * HARDWARE:
 *   GPIO 25  = Relay 1 (active LOW: push LOW to energize UV lamp 1)
 *   GPIO 26  = Relay 2 (active LOW: push LOW to energize UV lamp 2)
 *   GPIO 27  = Buzzer (LEDC PWM @ 2700 Hz, 10-bit, 5 patterns)
 *   GPIO 34  = Door/PIR sensor (input-only pin, HIGH = open/motion)
 *   GPIO 33  = DHT22 (temperature + humidity, OneWire)
 *   GPIO 2   = Onboard LED (blinks on each valid packet in)
 *   
 * UART2:
 *   GPIO 16  = RX (receive from slave)
 *   GPIO 17  = TX (send to slave)
 *   Speed: 115200 baud, 8N1
 *
 * BEHAVIOR:
 *   • Relay logic: digitalWrite(pin, on ? LOW : HIGH)  [active LOW]
 *   • Buzzer patterns: 0=KEY, 1=OK, 2=WARN (low freq), 3=DONE, 4=ALARM
 *   • DHT22 reads every 2 seconds (Adafruit DHT library)
 *   • Sends telemetry every 500ms (flags + temp*10 + humidity %)
 *   • Responds to commands from slave (set relay, set buzzer, ping)
 *
 * DEBUGGING:
 *   Serial output (USB) shows:
 *     [INIT]     = initialization messages
 *     [DHT22]    = temperature/humidity reads (OK or FAIL)
 *     [STATE]    = full state every 2s (door, relays, temp, humidity)
 *     [RX]       = incoming packet type
 *     [RELAY*]   = relay state changes
 *     [BUZZER]   = buzzer pattern name
 *
 * ============================================================
 * SLAVE (ESP32-S3 CrowPanel) - Display + UI
 * ============================================================
 *
 * WIRING:
 *   Master TX17 ──> Slave RX44
 *   Master RX16 <── Slave TX43
 *   Master GND ──── Slave GND
 *
 * WHAT HAPPENS IN loop():
 *   1. sbx_uart_task() pumps incoming telemetry from master
 *      (non-blocking, caches door/relay/temp/humidity state)
 *   2. lv_timer_handler() runs the LVGL display/touch
 *   3. When UI calls sbx_hal_relay_set()/buzzer()/read_env(),
 *      these go through the UART link (fire-and-forget) not GPIO
 *
 * ============================================================
 * PROTOCOL (sbx_uart_protocol.h)
 * ============================================================
 *
 * Packet format (7 bytes):
 *   [0] header   (0xAA = master telemetry, 0xBB = slave command)
 *   [1] type     (message type: SBX_MSG_TELEMETRY, SBX_CMD_SET_RELAY, etc.)
 *   [2..5] data[4]  (payload, meaning depends on type)
 *   [6] checksum (XOR of all fields)
 *
 * Message types:
 *   Master -> Slave:
 *     0x10 = TELEMETRY  (flags + temp*10_LE + hum%)
 *     0x11 = PONG       (ping reply)
 *
 *   Slave -> Master:
 *     0x01 = SET_RELAY  (data[0]=relay_id, data[1]=on)
 *     0x02 = SET_BUZZER (data[0]=pattern)
 *     0x03 = PING       (link test)
 *
 * Telemetry flags (data[0]):
 *     bit0 = door open
 *     bit1 = relay1 on
 *     bit2 = relay2 on
 *     bit3 = DHT22 valid
 *
 * ============================================================
 * UPLOAD CHECKLIST
 * ============================================================
 *
 * MASTER (SteriBox_Master folder):
 *   [ ] Install Adafruit DHT library in Arduino IDE
 *   [ ] Check pin map matches your wiring (top of SteriBox_Master.ino)
 *   [ ] Compile & upload SteriBox_Master.ino to ESP32-S
 *   [ ] Open Serial Monitor (115200 baud) -> should see boot messages
 *   [ ] Verify: relays HIGH (off), buzzer silent, DHT22 reading OK
 *
 * SLAVE (UI-2/UI folder):
 *   [ ] Verify sbx_uart_protocol.h exists (byte-identical to master)
 *   [ ] Verify steribox_uart.h/.cpp exist
 *   [ ] Verify steribox_hal_esp32.cpp includes steribox_uart.h
 *   [ ] Verify UI.ino includes steribox_uart.h and calls sbx_uart_task()
 *   [ ] Compile & upload UI.ino to ESP32-S3 CrowPanel
 *   [ ] On both boards: verify Serial output shows no errors
 *
 * ============================================================
 * TROUBLESHOOTING
 * ============================================================
 *
 * Master Serial shows "DHT22 FAIL" repeatedly:
 *   - Check DHT22 wiring (GPIO 33, 3.3V, GND, 10k pullup on data)
 *   - Adafruit DHT library: min 2s between reads, high failure rate normal
 *
 * Master doesn't blink LED on relay commands:
 *   - Check UART wiring (TX17 <-> RX44, RX16 <-> TX43)
 *   - Open slave Serial Monitor -> should see [RX] logs when commands sent
 *   - If no [RX] on slave, packets not arriving (bad wiring or UART config)
 *
 * Relay never turns on (stays HIGH):
 *   - Verify GPIO 25/26 are correctly wired to the relay module
 *   - Relay modules: active-LOW or active-HIGH? (ours = active LOW)
 *   - Breadboard test: manually pull GPIO 25 to GND with wire -> relay clicks?
 *
 * Buzzer silent:
 *   - Verify GPIO 27 is wired to buzzer + pin
 *   - Test with: digitalWrite(27, HIGH/LOW) then listen (no PWM = beep only)
 *   - ledcWriteTone() works on ESP32 with channels 0-15 at fixed freq
 *
 * UI shows "link lost" or env/relays stuck at old values:
 *   - Master sends telemetry every 500ms
 *   - Slave caches it, UI reads cache -> no blocking on UART
 *   - If link breaks, UI keeps old values for 2s, then assumes defaults
 *   - Check master Serial: [STATE] should print every 2s
 *   - Check slave Serial: should see [RX] telemetry packets every 500ms
 *
 * ============================================================
 */
